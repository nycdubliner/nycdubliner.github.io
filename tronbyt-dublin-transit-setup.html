Tronbyt Dublin Transit Setup

A reproducible setup guide for converting a stock Tidbyt Gen1 into a locally managed Tronbyt that cycles between Luas arrivals for Blackhorse and Dublin Bus arrivals for Oblates stop 1987.

The full source and documentation live in nycdubliner/tronbyt-dublin-transit-setup.

Final Topology

  • Tronbyt server on http://<host>:8000
  • nextbus on http://<host>:8080
  • Flashed Tidbyt Gen1 polling Tronbyt over Wi‑Fi
  • Two custom Pixlet apps: blackhorse_luas and oblates_buses

What The Repo Contains

  • Exact app source for both display applets
  • Exported Tronbyt manager settings for the two live apps
  • A sanitized Windows deployment template for nextbus
  • Exact operational notes for the running display

Deployment Outline

  1. Run Tronbyt server using the official Docker deployment.
  2. Create an admin user and a device called display.
  3. Generate firmware for Tidbyt Gen1 from Tronbyt Manager.
  4. Flash the stock Tidbyt using the ESP web flasher. The Tronbyt Device Specific Notes for Tidbyt Gen1 troubleshooting recommend trying a USB-A to USB-C cable instead of USB-C to USB-C if flashing fails.
  5. Deploy nextbus and expose it on port 8080.
  6. Create two custom apps in Tronbyt Manager from the repo’s Pixlet files.
  7. Set brightness to 2, app cycle time to 15, and order the apps Luas first, buses second.

Changing Stops

To move the Luas app to a different stop, edit STOP_CODE and STOP_NAME in apps/blackhorse_luas/blackhorse_luas.star, then validate the stop against the Luas XML endpoint before pasting the updated source into Tronbyt Manager.

To move the bus app, edit BUS_STOP_QUERY and BUS_STOP_NAME in apps/oblates_buses/oblates_buses.star. If your backend host changes, also update API_BASE_URL. Validate with curl http://<host>:8080/arrivals?stop=<code> before saving the updated app in Tronbyt Manager.

Observed Live Values

  • Tronbyt server version: 2.2.0
  • Device firmware version: 1.6.1
  • Luas stop code: BLA
  • Bus stop query: 1987
  • Rendered bus API base URL in the live setup: http://192.168.0.153:8080/arrivals

Notes

This setup deliberately uses the public Luas feed directly and a separate local nextbus service for bus arrivals. The Dublin Bus app is styled to resemble the orange-on-black RTPI stop displays. The full guide avoids publishing secrets and assumes the reader can adapt LAN addressing, credentials, and Docker host placement as needed.
